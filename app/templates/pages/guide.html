User Guide

Rclone S3 Management UI is an interactive rclone interface for backup, restore, and data transfer. It puts every rclone backend behind a web interface: configure a remote once, then copy, sync, schedule and restore with live progress instead of hand-written scripts. The first four workflows cover almost everything you will do; the fifth is a reference for the Transfer Console, where operations 2 and 4 actually run.

The forms below are illustrations — nothing is saved and no transfer is started.

Workflow 1 · Add a Remote

A remote is a named connection to one storage location — an S3 bucket, a Cloudflare R2 account, Google Cloud Storage, B2, or even a local folder. You configure it once here, then refer to it by name everywhere else. How to configure an S3 bucket with credentials:

Good to know

  • · Secrets are encrypted at rest; the UI shows “(unchanged)” on edit.
  • · Every backend rclone supports is available, including local and SFTP.

Workflow 2 · Run a One-Time Backup

Copy data from one bucket to another. Pick an operation, a source and a destination, then start it — the quickest way to move or protect data once, without setting up a schedule.

Example: copy a bucket

Copy is safe to repeat — it skips files already at the destination. Sync also deletes extras there, so choose it only when that is what you want.

Workflow 3 · Schedule a Recurring Backup

Set up automatic backups using cron-like scheduling. A job remembers a source, a destination and a schedule, then runs on its own — no cron scripts and no terminal left open.

Example: nightly backup

Pick a preset and the equivalent cron expression is filled in below.

At 02:00 every day.

Backups run automatically. Monitor them on the Dashboard. Each scheduled run appears with its status, and the Dashboard shows running jobs, success/failure counts and total bytes moved.

Good to know

  • · A job can be toggled off without being deleted.
  • · “Run now” starts one immediately without waiting for the schedule.
  • · Every run is audited, so you can see who changed what and when.

Workflow 4 · Restore from Backup

Recover data to a different bucket or location. Because backups keep dated archives, you can restore the bucket exactly as it looked on a given day — not just the latest copy.

Example: recover yesterday's files

Only dates that actually hold an archive are listed.

The restore streams live progress just like a copy, so even a large recovery is visible while it runs.

Restoring overwrites files. Use a test bucket first if unsure. Files at the destination are replaced with the archived versions. Restore into a scratch location, check it, then copy what you need into place.

Good to know

  • · You can restore a single path, not just the whole bucket.
  • · Old snapshots are pruned automatically after the retention window.
  • · A dry run first shows exactly what would change.

Workflow 5 · The Transfer Console

The Transfer Console (/transfers) is where workflows 2 and 4 actually run. It is not just “backup” — it is the front door to every rclone operation this app supports, run one at a time with live progress. Pick an operation, fill the form, press Run, and watch the Live run card.

The screen has three panels

  • 1 · Operation — the picker at the top left. Changing the button re-renders the form below with the fields that operation needs.
  • The form — source and destination remotes, buckets and paths, plus a collapsible Options (rclone flags) section with the real rclone flags for that operation.
  • Live run — the card on the right. It appears as soon as you press Run and refreshes about once a second until the run finishes.

A path browser sits underneath: choose a remote and folder to fill the path fields without typing them by hand.

Open the Transfer Console →

Every available operation

These are the real operations, grouped exactly as the console groups them.

Copy & sync

  • · Copy — new and changed files only, deletes nothing. Safe to repeat.
  • · Sync — makes the destination identical, deleting extras.
  • · Copy to (single object) — one file/folder to an exact name.

Move & delete

  • · Move — copy then delete the source. Irreversible.
  • · Move to (single object) — one item to an exact name.
  • · Delete files / Purge folder — remove data at the source.
  • · Clean up empty folders — prune empty directories.
  • · Two-way sync — changes propagate both ways.

Verify, maintenance, inspect

  • · Verify (check) — report missing/different files; transfers nothing.
  • · Verify encrypted remote — confirm a crypt remote decrypts correctly.
  • · Find duplicates — always a dry run, so it can delete nothing.
  • · Measure size — total size and object count of a path.

Destructive operations ask first

Anything that removes or overwrites data — Sync, Move, Delete, Purge, Two-way sync — shows a red confirmation box before it can run, and needs that box ticked. Prefer a dry run in Options when you are unsure: it reports what would change without touching anything.

Two-way sync needs a first run with --resync before it will do anything.

Reading the Live run card

  • · Objects — files or checks done, out of the total.
  • · Transferred / Total / Remaining — bytes moved so far and left.
  • · Speed and ETA — current rate and time remaining.
  • · Elapsed, plus Deleted, Errors and Listed when the operation produces them.

The bar turns green on success and red on failure. Every run — manual or scheduled — is kept in History with a full log you can open. A running transfer can be cancelled from the card.
